# karaoke-trainer

自分専用のカラオケ練習アプリ（個人利用）。

**Web アプリ: https://asaka6.github.io/karaoke-trainer/** （スマホ可・マイク使用・データは端末内のみ）

| タブ | できること |
|---|---|
| フリー | リアルタイムの音名・セントのズレ・横スクロールの音程グラフ |
| 音域 | 0.5 秒以上安定して出せた音だけ採用し、地声／裏声別に最低音・最高音を記録（端末に保存） |
| ボイトレ | 目標音を鳴らし、同じ音を出したときの平均ズレと安定度を表示 |
| 曲 | 曲ライブラリ（一度入れた曲は端末の IndexedDB に保存・フォルダごと追加可）。伴奏を流しながらガイドメロディと自分のピッチを重ねて表示（合っている所は緑）。キー変更 ±6 とおすすめキー、歌い出しカウントダウン、曲全体のタイムライン。歌い終わると採点・自己ベスト記録・ズレた区間からのやり直し |
| 選曲 | 測った音域と `index.json`・ライブラリの曲を照らし合わせ、そのまま歌える曲／キーを何個変えれば歌える曲を一覧。ライブラリの曲はタップでおすすめキーのまま練習へ |

## 構成

- `web/` … ブラウザアプリ（Vite + TypeScript、フレームワークなし）。`main` に push すると GitHub Actions がテスト → ビルド → Pages にデプロイ
- `pipeline/` … 曲データ前処理 CLI（Python: Demucs で分離 → torchcrepe/pyin で F0 → 音符化）。使い方は [pipeline/README.md](pipeline/README.md)

> 音源・分離した音声・抽出したメロディ JSON は著作物由来のため **コミットしない**（`.gitignore` で `songs/`・音声拡張子・`index.json` などを除外済み）。
> Web アプリは曲データをサーバーから読まず、ユーザーがファイル選択で端末内から読み込みます。

## 使い方の流れ

1. PC で `pipeline/` をセットアップし、手元の音源を処理 → `songs/` に曲 JSON・伴奏 MP3・`index.json` ができる
2. スマホで使うなら `songs/` をクラウドドライブ等でスマホへ
3. Web アプリの「音域」タブで地声・裏声の音域を測る
4. 「選曲」タブで `index.json` を選ぶ → 歌える曲とおすすめのキーが出る
5. 「曲」タブで `曲ID.json` と `accompaniment.mp3` を一緒に選び、キーを合わせて ▶ 開始

Space キーで開始／停止（曲タブ）・マイクのオン/オフ（他のタブ）。マイク使用中は画面がスリープしません。

イヤホン推奨（スピーカーの伴奏をマイクが拾うと音程判定が乱れます）。
自分の線がガイドより遅れて見える場合は「再生の設定 → 遅延補正」を調整してください（Bluetooth イヤホンは 150〜300ms）。

## 開発

```bash
cd web
npm install
npm run dev        # http://localhost:5173
npm test           # 単体テスト（合成サイン波でのピッチ推定精度・採点・選曲・キー変更）
npm run e2e        # 実ブラウザ（ローカルの Chrome）での動作確認。偽マイクに合成音声を入れる
```

動作確認用の URL パラメータ:

- `?test=440` … マイクの代わりに 440Hz のサイン波を入力
- `?test=guide` … 曲タブのガイドメロディをそのまま入力（＝完璧に歌った状態）

## しくみのメモ

- **ピッチ推定**: YIN アルゴリズム（`web/src/audio/yin.ts`）を AudioWorklet 内で約 10ms ごとに実行。48kHz は 2 倍間引きして計算量を 1/4 に。音量（-50dBFS 未満）と周期性（clarity 0.75 未満）で無音・無声を判定し、直近 3 フレームのメディアンで単発の誤推定を除去
- **キー変更**: 位相ボコーダ（ピーク位相ロック）で時間伸縮 → リサンプルでテンポを保ったまま音程だけ変える。Web Worker で処理し、キーごとにキャッシュ
- **採点**: 音程はオクターブ違いを許容し ±50 セント以内を正解。安定性はビブラート成分を平滑化で除いた揺れの標準偏差。ビブラートは 4.5〜8Hz・±15 セント以上の周期的変動を自己相関で検出
